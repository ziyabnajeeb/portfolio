# DESIGN_SYSTEM.md

Version: 1.0

---

# Purpose

This document defines the visual language and reusable design principles for the portfolio.

It is **not** a component library specification.

It defines how the UI should feel, behave, and remain consistent.

---

# Design Principles

The interface should feel:

* Premium
* Minimal
* Modern
* Calm
* Confident
* Professional

Every visual decision should support usability.

Avoid decoration for decoration's sake.

---

# Design Inspiration

Use products such as:

* Vercel
* Linear
* Raycast
* Stripe
* Apple
* Framer

Do not copy their UI.

Instead, adopt similar principles:

* Strong hierarchy
* Excellent spacing
* Clear typography
* Consistent layouts
* Subtle motion

---

# Layout Principles

Always design mobile-first.

Prefer generous whitespace.

Content should breathe.

Avoid crowded layouts.

Use consistent spacing throughout the application.

---

# Typography

Typography is the primary design element.

Prefer:

* Large headings
* Comfortable line height
* Clear hierarchy
* Readable paragraph width
* Consistent spacing

Avoid excessive font sizes and decorative fonts.

---

# Color System

Use a neutral-first palette.

Accent colors should be limited.

Avoid:

* Rainbow gradients
* Highly saturated colors
* Multiple competing accent colors

Color should reinforce content, not dominate it.

---

# Border Radius

Use a consistent radius scale across the application.

Avoid mixing multiple radius styles.

---

# Shadows

Shadows should be subtle.

Use elevation only when it improves hierarchy.

Avoid heavy shadows.

---

# Spacing

Spacing should be predictable.

Use a consistent spacing scale.

Prefer whitespace over visual separators.

---

# Icons

Icons should support comprehension.

Avoid decorative icons.

Use a single icon library throughout the project.

---

# Buttons

Buttons should clearly communicate hierarchy.

Variants:

* Primary
* Secondary
* Ghost
* Outline
* Destructive

Keep styling consistent across all variants.

---

# Cards

Cards should:

* Group related information
* Maintain consistent padding
* Use subtle elevation
* Have consistent border radius

Avoid excessive nesting.

---

# Forms

Forms should:

* Be simple
* Validate clearly
* Display helpful error messages
* Maintain consistent spacing
* Provide clear focus states

---

# Motion

Motion should:

* Guide attention
* Improve perceived performance
* Provide feedback
* Reinforce hierarchy

Avoid animations that delay interaction.

Respect reduced motion preferences.

---

# Responsive Design

Design mobile-first.

Enhance progressively for larger screens.

Do not sacrifice the mobile experience for desktop layouts.

---

# Accessibility

Every UI component should:

* Be keyboard accessible
* Preserve visible focus
* Meet color contrast requirements
* Use semantic HTML

Accessibility is part of the design system.

---

# Component Principles

Reusable components should be:

* Small
* Predictable
* Composable
* Generic

Avoid business-specific logic inside shared UI components.

---

# Design Consistency

Before creating a new component:

1. Check if an existing component solves the problem.
2. Extend existing components before creating new ones.
3. Keep naming consistent.
4. Maintain visual consistency.

---

# Final Principle

The design system should make the application feel like one cohesive product rather than a collection of individual pages.
